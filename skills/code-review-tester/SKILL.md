# Skill: Code Review & Tester

## Description

针对 `/Users/bytedance/Desktop/常见python/manju_web` 项目的代码审查与测试生成技能。

主要功能：
1. **代码审查（CR）**：全面审查代码质量、风格、安全性、性能等方面
2. **CR结论输出**：给出明确的审查结论（通过/不通过）和详细的改进建议
3. **单元测试生成**：自动为代码生成单元测试用例
4. **集成测试生成**：自动生成本地集成测试用例

## Workflow

### Step 1: 审查范围确认

在开始审查前，必须先完成此步骤。

1. **确定审查范围**：
   - 确认需要审查的文件或模块
   - 如果用户没有指定，询问具体的审查范围
   - 可以是单个文件、多个文件、整个模块或整个项目

2. **项目结构分析**：
   - 查看项目的整体结构
   - 了解代码的组织方式
   - 识别关键的业务逻辑模块

3. **技术栈确认**：
   - 确认项目使用的编程语言和框架
   - 了解现有的测试框架和测试结构
   - 查看 `conftest.py` 等测试配置文件

### Step 2: 代码审查执行

按照以下维度进行全面的代码审查：

#### 2.1 代码风格与规范
- **命名规范**：检查变量、函数、类的命名是否符合项目规范
- **代码格式**：检查缩进、空格、换行等格式是否一致
- **注释质量**：检查是否有必要的注释，注释是否清晰准确
- **导入规范**：检查导入语句的组织和顺序

#### 2.2 代码质量
- **单一职责**：检查函数/类是否遵循单一职责原则
- **可读性**：检查代码是否易于理解和维护
- **可维护性**：检查代码结构是否合理，是否便于修改和扩展
- **重复代码**：检查是否有重复代码可以抽取

#### 2.3 安全性
- **输入验证**：检查是否对用户输入进行了充分验证
- **异常处理**：检查异常处理是否完善，是否有裸 except
- **敏感信息**：检查是否有硬编码的密码、密钥等敏感信息
- **SQL注入**：检查SQL查询是否存在注入风险（如果有）

#### 2.4 性能
- **循环优化**：检查是否有可以优化的循环
- **数据库查询**：检查是否有N+1查询问题
- **资源管理**：检查文件、网络连接等资源是否正确关闭
- **算法效率**：检查算法的时间复杂度是否合理

#### 2.5 类型注解与文档
- **类型注解**：检查Python函数是否有完整的Type Hints
- **文档字符串**：检查是否有Google风格的docstring
- **参数说明**：检查参数和返回值是否有清晰的说明

### Step 3: 测试用例生成

#### 3.1 单元测试生成
1. **分析目标代码**：
   - 理解函数/类的功能和逻辑
   - 识别输入参数和输出结果
   - 分析边界条件和异常情况

2. **生成测试用例**：
   - 正常情况测试
   - 边界条件测试
   - 异常情况测试
   - 使用 pytest 框架编写测试
   - 参考项目现有的测试文件结构（如 `tests/conftest.py`）

3. **测试文件位置**：
   - 单元测试放在 `backend/tests/` 目录下
   - 命名规范：`test_<模块名>.py`

#### 3.2 集成测试生成
1. **确定集成点**：
   - 识别模块之间的交互
   - 确定API端点和调用链
   - 分析数据流和状态变化

2. **生成集成测试**：
   - 测试完整的业务流程
   - 测试模块间的协作
   - 使用临时目录和mock隔离测试环境
   - 参考 `conftest.py` 中的fixture配置

3. **测试文件组织**：
   - 集成测试可以放在 `backend/tests/` 目录下
   - 可以使用 `test_<模块名>_integration.py` 命名

### Step 4: CR结论输出

1. **审查总结**：
   - 总体评价（通过/不通过/有条件通过）
   - 主要优点
   - 主要问题

2. **问题分类**：
   - 严重问题（必须修复）
   - 中等问题（建议修复）
   - 轻微问题（可选修复）

3. **改进建议**：
   - 具体的修改建议
   - 代码示例（如果适用）
   - 参考资料链接

4. **测试报告**：
   - 生成的测试用例列表
   - 测试覆盖范围说明
   - 运行测试的命令

## Constraints

- **遵循项目规范**：代码审查和测试生成必须遵循项目现有的代码风格和架构模式
- **参考现有测试**：生成测试时必须参考项目现有的测试文件结构和风格
- **使用Type Hints**：Python代码必须使用类型注解
- **不破坏现有功能**：生成的测试不能破坏现有功能的正常运行
- **测试隔离**：测试必须使用临时目录和mock进行隔离，不影响真实数据

## Common Scenarios

### 场景1: 单个文件审查
1. 确认需要审查的文件路径
2. 对文件进行全面审查
3. 生成该文件中函数/类的单元测试
4. 输出CR结论

### 场景2: 新功能审查
1. 确认新功能涉及的文件
2. 审查新功能的代码质量
3. 生成新功能的单元测试和集成测试
4. 输出CR结论和测试报告

### 场景3: 整体代码质量提升
1. 对项目核心模块进行审查
2. 识别普遍存在的问题
3. 生成关键模块的测试用例
4. 给出整体改进建议
