# 调试模式和技巧

本文档记录了有效的调试模式和技巧，帮助快速定位和解决问题。

## 1. 系统性排查方法

### 1.1 二分法排查

当问题复杂且涉及多个组件时，使用二分法快速缩小范围：

1. **确定范围**：确认问题可能出现的组件列表
2. **中间点测试**：在流程中间点添加检查，确认问题出在前面还是后面
3. **递归细分**：对有问题的子范围继续二分，直到定位到具体位置

**示例**：
```
用户点击 → 前端JS → API请求 → 后端Handler → Service → Repository → 存储
     ↑        ↑         ↑          ↑           ↑          ↑           ↑
     检查点1  检查点2   检查点3    检查点4     检查点5    检查点6     检查点7
```

### 1.2 对比法排查

当有正常工作的参考案例时：

1. **找出差异**：比较正常案例和问题案例的所有差异
2. **逐一验证**：逐个消除差异，看问题是否消失
3. **定位根因**：找到导致问题的那个差异点

## 2. 日志分析技巧

### 2.1 关键日志位置

项目中的关键日志位置：
- `backend/logs/` - 主应用日志
- 终端输出 - 实时运行日志
- 浏览器控制台 - 前端日志

### 2.2 日志搜索模式

使用 Grep 工具快速搜索日志：

```python
# 搜索错误
Grep(pattern="ERROR|Exception|Traceback", path="/Users/bytedance/Desktop/常见python/manju_web/backend/logs", output_mode="content")

# 搜索特定函数
Grep(pattern="def submit_flow_phase", path="/Users/bytedance/Desktop/常见python/manju_web/backend", output_mode="files_with_matches")

# 搜索状态变更
Grep(pattern="status.*changed|state.*transition", path="/Users/bytedance/Desktop/常见python/manju_web/backend", output_mode="content")
```

### 2.3 日志时间线分析

1. 按时间排序日志条目
2. 标记问题发生的时间点
3. 查看问题发生前的相关操作
4. 追踪请求ID（如果有）的完整流程

## 3. 代码审查模式

### 3.1 常见错误模式检查清单

- [ ] **空值处理**：是否检查了 None/Null？
- [ ] **边界条件**：列表索引、循环终止条件是否正确？
- [ ] **类型错误**：数据类型转换是否安全？
- [ ] **并发问题**：共享资源是否有适当的同步？
- [ ] **错误处理**：异常是否被正确捕获和处理？
- [ ] **配置依赖**：硬编码值是否应该从配置读取？
- [ ] **数据一致性**：相关数据是否同步更新？

### 3.2 数据流追踪

追踪数据从输入到输出的完整流程：

1. **入口点**：用户输入/API请求
2. **验证层**：参数校验、数据清洗
3. **业务层**：核心逻辑处理
4. **数据层**：数据读写操作
5. **出口点**：响应返回/结果输出

在每个关键点检查：
- 数据格式是否正确
- 数据内容是否符合预期
- 数据转换是否丢失信息

## 4. 复现问题的策略

### 4.1 最小化复现场景

1. **移除无关因素**：逐步移除不影响问题的组件
2. **简化输入**：使用最简单的能触发问题的输入
3. **固定环境**：确保每次复现的环境一致
4. **记录步骤**：写下精确的复现步骤

### 4.2 不确定性问题的处理

对于偶发问题：

1. **增加日志**：在可疑区域添加详细日志
2. **压力测试**：增加触发频率，提高出现概率
3. **状态快照**：记录问题发生时的完整状态
4. **版本对比**：检查问题是在哪个版本引入的

## 5. 验证修复的方法

### 5.1 完整验证清单

- [ ] 问题确实被解决
- [ ] 没有引入新的问题
- [ ] 相关功能仍然正常工作
- [ ] 边界条件得到正确处理
- [ ] 错误情况有适当处理
- [ ] 性能没有明显下降
- [ ] 代码符合项目规范

### 5.2 回归测试

修复后检查：
1. 之前修复过的类似问题是否重现
2. 受影响模块的所有功能是否正常
3. 端到端流程是否完整工作
4. 用户界面的交互是否正常


### 6.2 Grep 使用模式

```python
# 按文件名搜索
Glob(pattern="**/*handler*.py")

# 搜索函数定义
Grep(pattern="^def ", type="py", output_mode="content", head_limit=50)

# 搜索类定义
Grep(pattern="^class ", type="py", output_mode="content", head_limit=30)
```

## 7. 协作调试

### 7.1 有效的问题描述

当向他人求助时，提供：

1. **清晰的症状**：发生了什么，预期是什么
2. **复现步骤**：精确的操作步骤
3. **环境信息**：版本、配置、相关数据
4. **已排查内容**：你已经做了什么尝试
5. **相关日志**：关键的错误信息和堆栈跟踪
